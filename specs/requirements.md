# Требования Backend Java

Сервис ККД использует Java 17, Spring Boot 3, Maven, PostgreSQL 16 и Liquibase.

## Приёмка

1. `docker compose up` собирает приложение, запускает PostgreSQL, выполняет миграции
   и создаёт 24 цели в трёх подразделениях и два завершённых прогона.
2. Модель включает иерархию подразделений, цели с ответственным, родителем, статусом
   и сроком, КР с target/actual/weight/updated_at, каталог правил, прогоны и проблемы.
3. Ровно четыре правила: GOAL_NO_OWNER (critical), KR_WEIGHTS_SUM (major),
   CASCADE_NO_PARENT (major), KR_STALE_PROGRESS (minor). Все проверяют только ACTIVE.
   Правила не обращаются к БД и HTTP, получают снимок и возвращают проблемы.
4. GET /api/runs возвращает статус, дату снимка, предыдущий успешный прогон и количество проблем.
5. GET /api/kkd/summary?run_id=&unit_id= возвращает три метрики, previous/delta/trend,
   higher_is_better, разбивку по трём важностям и new/persisting/resolved.
   Подразделение включает потомков; исторические числа берутся из снимков.
6. GET /api/kkd/issues поддерживает run_id, unit_id, rule_code, severity, limit, offset
   и дополнительно delta_status. Возвращает items, limit, offset, total.
7. Совпадение проблемы: rule_code + object_type + object_id. В первом прогоне
   поля compared_to и delta сводки равны null, как и previous, delta, trend у метрик. Текущие числа доступны.
8. 404 для неизвестных run/unit/issue, 422 для некорректных параметров.
   Единый ответ {"error":{"code":"...","message":"..."}}.
   Для FAILED/RUNNING результатов нет: 409 RUN_FAILED / RUN_IN_PROGRESS.
9. Liquibase выполняет накат, полный откат двух changeset и повторный накат.
   Проверка на настоящем PostgreSQL проводится в отдельной временной схеме.
10. JUnit 5 проверяет как минимум два правила на границах, метрики и дельту.
    Интеграционные тесты отдельно проверяют PostgreSQL, API и миграции.
11. README содержит команды запуска, тестирования и отката, описание архитектуры и ссылки на спецификацию и мотивацию участия.

## Дополнительные методы

GET /api/meta — подразделения, правила, важности. GET /api/kkd/issues/{id} — подробности.
POST /api/runs — запуск проверки текущих данных с явно заданной датой snapshot_date.
Прогон синхронный, новый снимок должен быть позже предыдущего успешного.
Планировщик, авторизация, CRUD целей и фронтенд не требуются.
