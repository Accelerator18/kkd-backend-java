# Контроль качества данных по целям

Java-сервис проверяет цели сотрудников и их ключевые результаты (КР). Каждый прогон сохраняет снимок данных и найденные проблемы в PostgreSQL. Через REST API можно посмотреть сводку по подразделению и изменения с предыдущей проверки.

Стек — Java 17, Spring Boot 3.5.7, PostgreSQL 16, Liquibase и Maven.

## Запуск

Из корня проекта выполните:

```bash
docker compose up
```

При первом запуске Docker скачает образы и зависимости Maven. После старта сервиса проверьте список прогонов и сводку по всей организации:

```bash
curl -fsS http://localhost:8080/api/runs
curl -fsS 'http://localhost:8080/api/kkd/summary?run_id=RUN-002&unit_id=HQ'
```

В демоданных 3 подразделения, 24 цели (21 активная) и 48 КР. В каждом прогоне есть нарушения всех четырёх правил.

| Прогон | Дата снимка | Проблемы | Доля корректных целей в HQ | Новые / сохраняющиеся / исправленные |
|---|---|---:|---:|---|
| RUN-001 | 26.10.2026 | 12 | 42,9 % | Сравнения ещё нет |
| RUN-002 | 02.11.2026 | 11 | 47,6 % | 4 / 7 / 5 |

Настройки портов и реквизитов собраны в [.env.example](.env.example). Для изменения скопируйте его в `.env`. По умолчанию API доступен на порту 8080, PostgreSQL — на `127.0.0.1:5433`. Команда `docker compose down` останавливает сервисы. Снимки сохраняются в томе `pgdata`. При повторном старте демопрогоны не дублируются.

## API

| Запрос | Результат |
|---|---|
| `GET /api/runs` | Статус, дата снимка, предыдущий прогон и число проблем |
| `GET /api/kkd/summary?run_id=RUN-002&unit_id=HQ` | Метрики подразделения с потомками, разбивка по важности и сравнение |
| `GET /api/kkd/issues?run_id=RUN-002&unit_id=CIB&severity=major&limit=5&offset=0` | Страница проблем и общее число совпадений. Доступны также фильтры `rule_code` и `delta_status` |
| `POST /api/runs` | Новый прогон по текущим данным на указанную дату |
| `GET /api/meta`, `GET /api/kkd/issues/{id}` | Справочники и карточка отдельной проблемы |

Параметры, коды ошибок и примеры JSON приведены в [описании API](docs/api.md).

## Правила и расчёты

`RuleEngine` передаёт снимок компонентам в пакете `ru.kkd.rule`. Они проверяют только активные цели и их КР. Контроллеры находятся в `api`, расчёт метрик и сравнение — в `service`, SQL-запросы — в `repository`.

| Правило | Важность | Когда возникает проблема |
|---|---|---|
| GOAL_NO_OWNER | critical | Ответственный отсутствует или состоит из пробельных символов |
| KR_WEIGHTS_SUM | major | Сумма весов КР отличается от 100 %. У цели без КР сумма равна нулю |
| CASCADE_NO_PARENT | major | У цели нет родительской цели в вышестоящем подразделении. Для корневого подразделения проверка не нужна |
| KR_STALE_PROGRESS | minor | Дата обновления факта отсутствует или отстоит от даты снимка более чем на 45 дней |

Сводка включает выбранное подразделение и его потомков на дату прогона. Доля корректных целей — процент активных целей без проблем. Сервис также считает количество проблем и число затронутых целей. При нескольких нарушениях одна цель учитывается в последнем показателе один раз. Для пустого подразделения оба количества равны нулю, доля равна `null`.

Сервис сравнивает с последним успешным прогоном. Одна и та же проблема определяется правилом, типом и идентификатором объекта. При переводе цели в другой отдел сохранившаяся проблема учитывается в новом отделе. В первом прогоне `compared_to`, `delta`, а также поля `previous`, `delta` и `trend` у метрик равны `null`.

## Тесты и миграции

Модульные тесты можно запустить с JDK 17 через Maven Wrapper:

```bash
./mvnw test
```

Полная проверка, включая JUnit 5, MockMvc и Liquibase на PostgreSQL:

```bash
docker compose --profile tools run --rm tools -Pintegration verify
```

Для проверки только интеграционного сценария миграций используйте `-Dit.test=MigrationIT` вместе с `-Pintegration verify`. Тест выполняет накат, частичный и полный откат, повторный накат и проверку повторного запуска без изменений. Для каждого интеграционного набора создаётся отдельная временная схема.

При локальном запуске укажите `IT_DB_URL`, `IT_DB_USER`, `IT_DB_PASSWORD` и выполните `./mvnw -Pintegration verify`. Для ручной проверки миграций в **отдельной тестовой БД** с остановленным приложением экспортируйте `DB_URL`, `DB_USER`, `DB_PASSWORD` и выполните:

```bash
./mvnw liquibase:update
./mvnw liquibase:rollback -Dliquibase.rollbackCount=2
./mvnw liquibase:update
```

Полный откат удаляет таблицы модуля. Миграции загружают исходные данные, а два демопрогона рассчитываются при старте приложения. Переменная `SEED_DEMO=false` отключает создание этих прогонов.
